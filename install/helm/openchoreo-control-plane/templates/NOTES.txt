The portal is disabled, but this chart cannot remove authorization objects an
earlier install already created: the authz bootstrap only ever applies. If this
release previously ran the portal, its catalog-reader grant is still in the
cluster and still gives the portal's OAuth client cluster-wide read access.
Check, and drop it if you no longer want it:
  kubectl get clusterauthzrole backstage-catalog-reader
  kubectl delete clusterauthzrole backstage-catalog-reader
  kubectl delete clusterauthzrolebinding backstage-catalog-reader-binding
The matching ThunderID application outlives the chart too, and is removed
through the ThunderID management API.
