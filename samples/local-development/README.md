# Local development with `occ remote`

`occ remote` gives application developers a fast inner loop: it resolves a workload's declared **endpoint dependencies** for an environment, opens a local TCP listener for each remote one, and drops you into a subshell whose environment variables point at those listeners — so your code runs on your machine against the environment's real upstreams.

This sample is self-contained: it seeds the endpoint providers in the cluster and then runs `occ remote` against a consumer that depends on them.

- **Endpoint providers** — `greeter-service` (HTTP, in the `greeter` project) and `grpc-greeter` (gRPC, in the `grpc-demo` project). They live in **separate projects** to exercise cross-project dependencies.
- **Consumer** — `workloads/service-test-workload.yaml` declares endpoint dependencies on both providers; `occ remote` tunnels them to your machine.

```
local-development/
├── dependant-comps/                               # endpoint-dependency providers (each self-creates its project)
│   ├── greeter-project/greeter.yaml               #   HTTP provider  → project `greeter`
│   └── grpc-demo-project/grpc-greeter.yaml         #   gRPC provider  → project `grpc-demo`
└── workloads/                                     # the consumer you run with `occ remote`
    └── service-test-workload.yaml                 # endpoint deps → greeter, grpc-greeter
```

## Prerequisites

- Remote-connect enabled on both planes (both default to off): `openchoreoApi.config.remoteConnect.enabled` on the control plane, with an `entrypointAddress` your machine can reach, and `remoteAgentRouter.enabled` on the data plane. On k3d that address is `127.0.0.1:30443`, matching the router's NodePort.
- `occ` **v1.3.0+** (the `occ remote` command), and `occ login` completed. On a k3d install the seeded developer is `developer@openchoreo.dev` / `Dev@123` (group `developers`).

No key or certificate setup is required. The capability signing key is generated by the control-plane chart, and each remote-agent's TLS cert is generated on first use and pinned by `occ`.

## What you can tunnel

`occ remote` resolves **each dependency separately** and tunnels the ones your role may reach: your role needs the `component:connect` action covering that dependency's component.

Nothing is checked about the component you are running. It does **not** need to exist in OpenChoreo, so you can tunnel dependencies for a component before its first deploy, and try new dependencies before committing them. Access is decided per dependency, by role — endpoint visibility governs traffic between deployed workloads and does not restrict `occ remote`.

Dependencies you cannot reach are listed as unavailable and the rest still tunnel. The message is deliberately the same whether the component is undeployed or your role has no access to it.

A session is capped by the capability lifetime (`remoteConnect.ttlSeconds`, 30 minutes by default). Connections already open keep working, but new ones stop being accepted once it lapses and `occ remote` prints `session expired`. Exit the subshell and re-run to reconnect. Revoking a role also only takes effect at the next session, for the same reason.

### Permissions for this sample

Your role needs `component:connect` on **each component you depend on** — bound to that component, or to a scope above it (its project, its namespace, or cluster-wide). The component you are running needs no grant of its own. Here that means `greeter-service` and `grpc-greeter`; the built-in `developer` role covers both on a stock install.

See the [Local Development guide](https://openchoreo.dev/docs/next/developer-guide/dependencies/local-development) for the full walkthrough.

## 1. Seed the endpoint providers

Apply the two provider components. Each file creates its own project + development binding and the component; `autoDeploy: true` rolls them out and publishes their endpoints, which `service-test` depends on:

```bash
kubectl apply -f samples/local-development/dependant-comps/greeter-project/greeter.yaml
kubectl apply -f samples/local-development/dependant-comps/grpc-demo-project/grpc-greeter.yaml
```

## 2. Run `occ remote`

Tunnel the greeter and grpc-greeter endpoints to your machine:

```bash
occ remote samples/local-development/workloads/service-test-workload.yaml \
  --namespace default --env development
```

Inside the subshell, `HTTP_SERVICE_URL` and `GRPC_SERVICE_URL` each resolve to a `127.0.0.1:<port>` listener tunnelled to the respective endpoint; exit the subshell to tear every tunnel down.

See the [Local Development guide](https://openchoreo.dev/docs/next/developer-guide/dependencies/local-development) for the full walkthrough, `--print-env`, and multi-workload cross-linking (`--local`).
